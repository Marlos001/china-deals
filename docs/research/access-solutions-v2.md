# Account-free marketplace access: solution review, v2

Research snapshot: 2026-10-27. This includes a source review, additional root tests below, and the **prior** bounded observations in [guest-access.md](guest-access.md), not a claim of new live marketplace tests. Scope: Taobao/Tmall, JD and Goofish search/detail and prices, without marketplace accounts. No account was created, extension installed, purchase or message made, or third-party code executed. Earlier Goofish risk response and JD verification redirect are stop signals; they were not retried. The existing [framework review](frameworks.md) and [marketplace review](marketplaces.md) contain wider source and adapter detail.

## XianyuKit and extension reality

[naustagic/XianyuKit](https://github.com/naustagic/XianyuKit/tree/4a09e71ee2cb1f77b1a54a0f2fde8bc57a8d4310), pinned commit `4a09e71ee2cb1f77b1a54a0f2fde8bc57a8d4310`, manifest **1.0.0**, was last pushed 2026-08-22 according to GitHub API; API showed zero issues and no declared license, and the captured tree has no LICENSE file. This is a small maintenance signal, not a guarantee of compatibility or abandonment. Do not copy code without licensing clarification. [Manifest](https://github.com/naustagic/XianyuKit/blob/4a09e71ee2cb1f77b1a54a0f2fde8bc57a8d4310/manifest.json) requests `storage`, `scripting`, `alarms` and host access to Goofish, Taobao and exchange-rate services. It is not configured for JD.

Source inspection shows Goofish and Taobao [login-overlay strategies](https://github.com/naustagic/XianyuKit/blob/4a09e71ee2cb1f77b1a54a0f2fde8bc57a8d4310/src/content-scripts/modules/close_login_light/sites/goofish.js) and [Taobao strategy](https://github.com/naustagic/XianyuKit/blob/4a09e71ee2cb1f77b1a54a0f2fde8bc57a8d4310/src/content-scripts/modules/close_login_light/sites/taobao.js) hide/remove page elements and restore scrolling; the latter also targets a Baxia verification dialog. The [price DOM module](https://github.com/naustagic/XianyuKit/blob/4a09e71ee2cb1f77b1a54a0f2fde8bc57a8d4310/src/content-scripts/modules/price_brl/price-dom.js) transforms page price text, and the [rate worker](https://github.com/naustagic/XianyuKit/blob/4a09e71ee2cb1f77b1a54a0f2fde8bc57a8d4310/src/service-worker/exchange-rate.js) calls external exchange-rate providers. This does not establish guest search, fetching prices absent from server responses, or a valid coupon price. This overlay logic was not integrated: it also targets a verification dialog, and cosmetic suppression alone does not establish access to the underlying search or price data. Static reading of selected files is not a full extension security review.

The separately published [Chrome Web Store listing also named XianyuKit](https://chromewebstore.google.com/detail/xianyukit/lamfpellmoneeemgfgffdjefopgpnjak) identifies publisher GVTECH, version **1.2.51**, updated June 29, 2026, and declares handling personally identifiable information. The repository's version and publisher do not establish that it is this store package; **identity and code equivalence unverified**. Its listing advertises conversions, local history, seller visuals and CSSBuy shortcut, not proven server-side access. The listings for [CoelhoLifeStyle helper](https://chromewebstore.google.com/detail/coelholifestyle-xianyugoo/liphblnnkdkiocnlomngjjgbnicpmped) and [CSSBuy Xianyu Helper](https://chromewebstore.google.com/detail/cssbuy-xianyu-helper/pdjhhconfbiklmdcdmfkndoomnllggpo) advertise popup removal and conversion; those are publisher claims, not audited behavior. Store versions, licenses, code identity and live functionality for these two were not pinned. The former advertises exchange-rate and optional translation network calls; the latter advertises an optional affiliate purchase link. None proves complete guest catalog search or recovery of server-withheld values.

**Masked-price distinction:** if the actual price was delivered in the DOM behind a purely visual layer, a display tool may reveal or convert it; if the response omits it, contains an encoded placeholder, or contains a different channel/list price, cosmetic CSS cannot reconstruct it. An [OpenCLI issue #2162](https://github.com/jackwener/OpenCLI/issues/2162) reports specific Tmall subsidized listings where the rendered/hydration price differs from search-page price even in a logged-in session, as well as ordinary extraction errors. This is a reporter's reproducible claim, not independently verified here; absence of `extraPrice` also occurs for ordinary items, so it is not a universal decoy detector. Never infer a final price from a guessed placeholder or a fixed ¥9999 rule. Keep price kind, selected SKU, currency, coupon conditions and source context explicit; unknown remains unknown.

## Search APIs and fields

[OneBound's Taobao documentation](https://open.onebound.cn/help/api/taobao.item_search.html) lists keyword, price range, page, category, sort, seller and filters for free shipping, Tmall, second-hand and location; example fields include item ID, title, price, promotion price, image, seller and 30-day volume. Its [JD search docs](https://open.onebound.cn/help/api/jd.item_search.html) list keyword, price bounds, category, page, sorting, detail URL, title and image, and require key/secret. Its example has a discount flag, but the page does not prove coupon amounts, eligibility or final checkout price. Some examples put secrets in URLs and disable TLS verification; do not copy these practices. Review current signed authentication and keep secrets off client URLs/logs; verify schema, retention, permitted use, limits, fee, stale-cache semantics and upstream dependencies with provider before integration. Provider's version field is optional and no concrete version was established.

The pinned MIT [Shopping MCP](https://github.com/EastMG/dsh-shopping-mcp/tree/22190059ea1007050e2d0864e9afed3d05bd19c9) in the existing framework review wraps official Taobao/JD affiliate APIs and needs its own app credentials and platform authorization. Its mock fallback must be excluded from live comparison, and its own report says JD search received 403 in its particular account. A Taobao search ID can be opaque; do not assume every result ID is the numeric detail ID. Coupon support is affiliate and permission dependent, not a promise of all offers. It is not an account-free API.

The pinned [OpenCLI Goofish search implementation](https://github.com/jackwener/OpenCLI/blob/97dc0cd5214b9602bcda78d7422f231ee8a803e9/clis/xianyu/search.js) calls page-context mtop with `needLogin:false`, but its documentation and broader workflow require a logged-in browser. The flag does not establish server-granted guest access. Prior guest tests hit a risk response; never repeat or interpret it as an empty catalog. Existing `guest-access.md` details price/location/condition parameter candidates; they are third-party implementation observations rather than stable official guest contracts. Other Goofish tools in `frameworks.md` use persistent sessions, login or unverified selectors and may expose write operations; no autonomous guest adapter is proven.

For the JD legacy endpoint, source examples are not JD documentation and may be stale or require runtime state. Public address syntax does not prove anonymous entitlement, CORS, location neutrality, final price, availability, coupon application or production reliability. A bounded test needs a single known SKU and inspection of the application result as well as HTTP status; root performed that independent public-route test under the renewed scope, with the result below. Do not turn this into a scanner or use it as a substitute for a search index.

## Business registration and the original Reddit suggestion

The [specific Reddit discussion](https://www.reddit.com/r/taobao/comments/1g0kbi8/browsing_without_account/) contains a user's anecdote that a business account used email and also a phone number; another user questioned whether accounts remained usable. It is neither an official current requirement nor evidence that registration is available for every country. Disregard the suggestion to supply fictitious details. A business account would be an optional authenticated path; its current foreign-user eligibility and browsing benefit remain unverified.

The attempted official [Taobao registration entry](https://reg.taobao.com/member/reg/fill_mobile.htm) could not be opened by the research web tool, so we **cannot establish the current business registration form, real-email verification, real-phone verification, accepted country codes, foreign eligibility, identity documents or approval rules**. We did not enter data or begin registration. Alibaba's [IPP guidance](https://ipp.alibabagroup.com/instruction/cn.htm) describes a separate intellectual-property complaint account created using email, and accepts some existing marketplace identities for IPP login; it is not proof that an IPP account can browse Taobao, nor proof of Taobao business-account requirements. Current foreign-user options need direct official confirmation for the exact account type and region; do not generalize from IPP, 1688, a Reddit anecdote, or an unrelated Alibaba service.

## Integration recommendations and evidence

1. Model each provider separately: `source`, canonical item URL and ID, observed timestamp, search query and pagination, price amount/currency/type, SKU, condition, shipping, location, status, coupon/eligibility and raw evidence reference. Preserve `unknown`, `blocked`, `login_required`, `verification_required`, `partial`, `stale`, `delisted` and `error` separately from an actual empty result. Do not equate seller's stated condition with verified condition or agent price with final payable price.
2. Begin with independently discoverable public Goofish detail links and optionally the two agent catalog evaluations above. Deduplicate only on exact source marketplace plus ID, preserve original links, label source and agent data separately, and check availability before presenting an item. Mark unverified filters and coverage; never fill coupon or final price from a missing field.
3. Consider OneBound only as a contracted provider adapter after credential, pricing, legal/terms and data-quality review; no decision about legality is made here. Official affiliate APIs are a separate credentialed path. Enforce provider-specific capabilities, quotas and clear blocked states; do not automate session reuse or verification.
4. Price conversion should be a separate presentation calculation with rate, timestamp, source and stale indicator. Never change the original CNY value, and do not silently interpret listing, subsidy, coupon, shipping or selected-variant prices as equivalent.

A login button or a routine login-state-check request is not by itself a blocking wall. Conversely, hiding an overlay cannot supply a value absent from the delivered data. A normal user-owned browser session can also have useful anonymous cookies without a marketplace account; **guest does not inherently mean every request must have no cookies**. The current CLI HTTP/isolated-browser modes deliberately start fresh, which can differ from the user's ordinary browser. Explicit OpenCLI native/browser mode may read an already accessible browser page without implying that the user must create an account, but its bridge is not connected in this environment.

The Taobao overseas [service agreement](https://terms.alicdn.com/legal-agreement/terms/c_end_product_protocol/20240717213501393/20240717213501393.html) explicitly contemplates non-mainland phone/email/third-party registration and requires accurate contact information. That is primary evidence for foreign-user paths, not a verified +55 OTP delivery test or proof that a business registration bypass remains available. The 2024 Reddit anecdote does not establish today's form or remove later verification. No temporary email or fictitious phone was submitted.
